# 002 — Загрузчик игровых конфигов

## Цель и зависимости

После spec 001 реализовать однократное чтение JSON с типизированной валидацией.
Не зависит от spec 003: типы конфигурации выводятся из собственных схем.
Перед кодом представить план. Один spec — один PR.

## Читать

`AGENTS.md`, `docs/conventions.md`, `docs/architecture.md`,
`docs/config-schema.md`. Все поля и ограничения определены в config-schema.

## Разрешённые изменения и зависимости

`packages/shared/src/config/**`, shared exports/package.json, pnpm-lock.yaml,
`config/*.json`, `docs/config-schema.md`. Разрешена одна новая runtime-зависимость:
Zod 4 в shared. Использовать существующий Vitest.
Примеры в config синтетические, массивы можно оставить пустыми; не утверждать баланс.

## Вход и выход

Вход — rootDir, путь каталога из config-schema.
Выход — синхронная функция `loadConfig(rootDir: string): GameConfig`
в `packages/shared/src/config/loader.ts`.
Схемы — `schemas.ts`, выведенные типы — `types.ts`, ConfigError — `error.ts`.
Node entry point `config/node.ts` экспортирует загрузчик и ConfigError через
`@troll-vs-elves/shared/config/node`. Основной entry point экспортирует только
браузерные схемы/типы; в нём нет транзитивного Node I/O.

## Требования

- Прочитать все шесть обязательных файлов; JSON.parse считать unknown.
- Валидировать строгими Zod-схемами и проверять уникальность ID внутри файла.
- Ошибки чтения, JSON и схем оборачивать в ConfigError по контракту документа.
  Пользователь видит файл и поле; ошибки не проглатываются.
- Не использовать cwd как скрытую базу: пути разрешать относительно rootDir.
- Не кешировать глобально: каждый явный вызов читает свой rootDir. Один вызов
  при старте обеспечивает вызывающий код будущего сервера.
- Все модульные константы, в том числе схемы, через IIFE.

## Тесты

Создавать временные каталоги и удалять их после теста. Проверить:
валидный полный набор; пустые массивы; отсутствующий файл; некорректный JSON;
ошибочный вложенный hp (путь `[0, "hp"]` и файл); неизвестный ключ; повторный ID;
неверный порядок фаз/фаза за концом матча; отсутствие зависимости от cwd.
Проверить, что browser entry point не тянет Node I/O (проверка графа импортов
или сборки). Не добавлять отдельный bundler только ради этой проверки.

## Не делать

Не реализовывать hot reload, YAML, I/O в браузере, боевые эффекты,
сетевой протокол или чтение конфигурации каждый тик.

## Definition of Done

`pnpm --filter @troll-vs-elves/shared test`, `pnpm typecheck`, `pnpm test`,
`pnpm lint`, `pnpm build` проходят. Тесты проверяют ConfigError и его поля.
Контракт config-schema соответствует фактическим схемам и примерам config/.
