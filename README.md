# Troll vs Elves

Браузерная игра: один тролль против N эльфов, матч на 30 минут.
Выполнены specs 001–003 и 005–010: монорепозиторий, конфиги, базовые типы,
сетевой протокол, WS-сервер и первая игровая прогулка по лесу.
Работают движение, коллизии, несколько игроков, таймер и фазы. Экономика и бой впереди.

## Подготовка

Нужны Node.js из `.node-version` (24 LTS) и pnpm из `packageManager` в package.json.
Если pnpm ещё нет, установите закреплённую версию: `npm install -g pnpm@11.28.6`.
Из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm lint
pnpm build
```

`pnpm format` исправляет форматирование. Typecheck сначала собирает shared;
build выполняет сборку пакетов в порядке зависимостей. Есть тесты конфигов и протокола,
интеграционные тесты WS-сервера и проверки жизненного цикла клиентского подключения.
Пакеты: `@troll-vs-elves/shared`, `@troll-vs-elves/server`, `@troll-vs-elves/client`.
Для проверки отдельного пакета: `pnpm --filter @troll-vs-elves/shared test`.

## Конфиги и shared API

Схемы и типы импортируются из `@troll-vs-elves/shared`. Серверный загрузчик
`loadConfig(rootDir)` и `ConfigError` доступны отдельно через
`@troll-vs-elves/shared/config/node`. rootDir указывает на каталог `config/`,
а не на корень репозитория. Браузерный entry point не использует Node I/O.
Загрузчик не кеширует данные: будущий сервер должен вызвать его один раз до матча.
Значения характеристик сущностей ещё не утверждены.

## Серверный каркас (spec 006)

```sh
pnpm dev:server
```

Готовность: `http://127.0.0.1:3001/health`, WS: `/ws`. Остановка — Ctrl+C.
Можно задать HOST, PORT и GAME_CONFIG_DIR. По умолчанию конфиги находятся
относительно server/dist, поэтому команда не зависит от текущего каталога.
Сервер обслуживает одну временную комнату, движение и снапшоты с частотой из конфига.

## Игровая проба (specs 007–010)

После установки зависимостей запустите в двух терминалах:

```sh
pnpm dev:server
pnpm dev:client
```

Откройте `http://localhost:5173/`: подключение происходит автоматически. Vite
проксирует /ws и /health к server:3001; в браузере используется origin страницы,
в том числе wss при HTTPS. Для остановки обоих процессов — Ctrl+C в терминалах.
Текущая proxy-конфигурация предназначена для локальной разработки.

## Управление

- Клик или тап по земле — идти к точке. WASD / стрелки — движение.
- Обходите деревья и пруд: автоматического поиска пути пока нет.
- Первый участник — тролль, остальные — эльфы; до 8 участников.
  Откройте вторую вкладку, чтобы увидеть другого героя в той же комнате.
- «Выйти из леса» завершает подключение. Повторный вход даёт нового персонажа.
- Прогулка длится 30 минут; на нуле движение останавливается.
  Для новой пробы все участники должны выйти, затем войти снова.

Это первый прототип управления: боя, строительства, экономики и победы пока нет.
Графика PixiJS процедурная, без внешних ассетов. Геометрия и параметры персонажей
загружаются сервером из JSON с Zod-валидацией. Это временные настройки пробы.
Production-сборка клиента находится в packages/client/dist; deploy — отдельный этап.
