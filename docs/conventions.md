# Соглашения кода

## TypeScript и модули

Strict mode обязателен. `any` запрещён. На границах сети, JSON и файловой системы
использовать `unknown` и Zod. Только именованные экспорты.
Файлы — kebab-case, функции — camelCase, типы и классы — PascalCase.
Не импортировать исходники соседнего пакета относительным путём: использовать
публичные entry points пакетов. Server и client зависят только от shared.

## Константы: обязательная стрелочная IIFE

Все константы-значения уровня модуля, включая схемы, таблицы и настройки
инструментов в TypeScript/JavaScript, объявляются через стрелочную IIFE:

```ts
export const TICK_RATE = (() => 20)();
const RESOURCE_KEYS = (() => ["gold", "wood", "rage"] as const)();
const PHASE_START_SECONDS = (() => {
  const secondsPerMinute = 60;
  return [0, 10 * secondsPerMinute, 20 * secondsPerMinute] as const;
})();
```

Значение вычисляется при загрузке модуля, вычисление можно инкапсулировать внутри.
Обычный модульный инициализатор также вычисляется при загрузке; IIFE здесь —
обязательное соглашение о форме записи. IIFE не делает объект неизменяемым.
Для статической неизменяемости применять readonly/`as const`, когда это нужно.

```ts
// Запрещено на уровне модуля:
const MAX_PLAYERS = 4;
let maxPlayers;
maxPlayers = 4;

// Функция-утилита — исключение, это обычная функция:
export const toMilliseconds = (seconds: number): number => seconds * 1_000;
```

Локальные переменные, параметры, type/interface, объявления классов и функций
не требуют IIFE. Не оборачивать обработчики и фабрики в искусственные IIFE.
JSON/YAML не содержат JavaScript и этому правилу не подчиняются.
Значения в примерах не являются разрешением добавить игровой баланс в код.

## Данные и время

Игровые параметры читать из валидированного конфига; единицы измерения указывать
в названиях (`durationSeconds`, `speedUnitsPerSecond`). Сеть не передаёт локальные
таймеры как источник истины. Формулы shared — чистые, без I/O и часов ОС.
Побочные эффекты и состояние матча принадлежат server.

## Проверки

Vitest проверяет поведение, ошибки и граничные случаи модулей. Не создавать
фиктивные тесты ради зелёного CI. Тесты рядом с кодом: `*.test.ts`.
После spec 001 общие команды: `pnpm typecheck`, `pnpm test`, `pnpm lint`.
Форматирование проверяется в lint; сборка — `pnpm build`.
