# Архитектура

Это целевая структура; пакеты создаются по spec 001.

| Модуль            | Ответственность                                                   | Допустимые зависимости внутри проекта    |
| ----------------- | ----------------------------------------------------------------- | ---------------------------------------- |
| `packages/client` | Интенты, PixiJS, UI, отображение и интерполяция снапшотов         | Браузерные entry points shared           |
| `packages/server` | WS, комнаты, авторитетный тик 20 Hz, игровые проверки и состояние | shared, включая Node entry point         |
| `packages/shared` | Типы, Zod-схемы, чистые формулы, протокол                         | Ни client, ни server                     |
| `config`          | JSON с игровыми данными                                           | Не содержит исполняемого кода            |
| `tools/sim`       | Headless-симуляция, детерминированные боты и отчёты               | shared и публичная игровая логика server |

Поток: client → интент → валидация server → изменение состояния на тике →
снапшот, отфильтрованный для получателя → client.
Клиент не определяет урон, доход, доступность постройки или результат матча.

## Shared и файловая система

Имя пакета: `@troll-vs-elves/shared`; остальные — `@troll-vs-elves/server`
и `@troll-vs-elves/client`.
Браузерный entry point `@troll-vs-elves/shared` не экспортирует Node-загрузчик
и не импортирует `node:fs`/`node:path` транзитивно.
`@troll-vs-elves/shared/config/node` — отдельный Node entry point для загрузчика.
Схемы и типы можно использовать в браузере без чтения файлов.

`loadConfig(rootDir)` вызывается сервером один раз до запуска матча.
Симулятор использует ту же игровую логику, без подключения к WS.
Реализация сервера должна позднее отделить игровой цикл от транспорта.

## Выбор транспорта

Для первого каркаса используется `ws`. Colyseus не устанавливать параллельно;
смена транспорта требует отдельного spec и обновления контрактов.
Точные сетевые контракты вводятся в spec 005, см. `protocol.md`.

## Сетевой каркас (spec 006)

`server/main.ts` загружает config один раз и запускает `startGameServer`.
HTTP GET /health сообщает готовность; WS /ws обслуживает одну MatchRoom.
Комната выдаёт временные ID и очищает отключившихся игроков. Пока нет
игрового тика, распределения команд или изменения состояния по интентам.
Транспорт ограничивает размер, частоту и очередь сообщений по shared/constants.
