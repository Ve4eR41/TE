# Контракт сообщений

## Статус

Сетевой протокол ещё не реализован. Источником истины после spec 005 будет
`packages/shared/src/protocol.ts` с Zod-схемами и выведенными из них типами.
Публичные изменения требуют синхронного обновления этого документа.
Базовые типы spec 003 описаны отдельно и сами по себе не являются WS API.

## Область spec 005

Предусмотреть интенты `move`, `build`, `hire`, `upgrade`, `ability`, `buy`,
`subclass` и серверный снапшот с tick, entities, resources, phase, timeLeftSeconds.
Это список требований для проектирования, а не готовый wire format.

Перед реализацией определить: версию сообщений, единицы координат, полную или
дельта-передачу, удаление сущностей, идентификаторы, видимость и приватность
ресурсов, ответы на отклонённые интенты, ограничения размера/частоты и правила
переподключения. Типы должны однозначно отражать эти решения.

Все входящие сообщения считаются `unknown`, проходят runtime-валидацию,
а затем проверку игровых прав на сервере. Клиент не задаёт игрока-владельца,
урон, баланс ресурсов или номер авторитетного тика.

## Базовые типы состояния (spec 003)

Источник истины — [packages/shared/src/types.ts](../packages/shared/src/types.ts),
публичный импорт типов: `@troll-vs-elves/shared`.

| Тип                | Контракт                                                    |
| ------------------ | ----------------------------------------------------------- |
| EntityId, PlayerId | Строковые идентификаторы                                    |
| Team               | `"troll"` или `"elves"`                                     |
| Phase              | `1`, `2` или `3`                                            |
| Resources          | readonly `gold`, `wood`, `rage`: number                     |
| Position           | readonly `x`, `y`: number, игровые единицы                  |
| Entity             | readonly `id`, `ownerId`, `team`, `position`, `hp`, `maxHp` |

`ownerId` равен PlayerId или null (нет игрока-владельца). Team обязателен;
нейтральные сущности в этот контракт пока не входят. Position также readonly,
поэтому координаты нельзя менять через ссылку из Entity.
Это типы TypeScript для внутреннего состояния. Они не валидируют внешний JSON,
не проверяют игровые диапазоны HP/ресурсов и не определяют WS-сериализацию.
Сетевой wire format ещё не определён и будет введён spec 005.
