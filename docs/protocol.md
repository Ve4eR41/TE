# Контракт сообщений

## Wire format v2 (specs 005, 009–010)

Источник истины: [packages/shared/src/protocol.ts](../packages/shared/src/protocol.ts).
Схемы Zod, выведенные типы и безопасные декодеры экспортируются из shared.
Сообщения — UTF-8 JSON, только текстовые WS-кадры, строгие объекты с `v: 2` и `t`.

| Направление / t | Поля кроме v и t                                       |
| --------------- | ------------------------------------------------------ |
| Client ping     | requestId                                              |
| Client intent   | requestId, intent                                      |
| Server welcome  | playerId, roomId, match, map (параметры матча и карта) |
| Server pong     | requestId                                              |
| Server error    | code, requestId?                                       |
| Server snapshot | tick, entities, resources, phase, timeLeftSeconds      |

Intent: move(x,y), steer(x,y), build(buildingId,x,y), hire(unitId), upgrade(entityId),
ability(abilityId,target?), buy(itemId), subclass(id). Координаты конечные,
в игровых единицах; границы карты и допустимость действий проверяет server.
ID — непустые строки без пробелов по краям, до 64 символов. requestId назначает
клиент для корреляции ответа. playerId выдаётся сервером, в интенте его нет.

Snapshot передаёт полное состояние, разрешённое получателю, а не дельту.
Отсутствующая сущность удаляется на клиенте. Resources принадлежат только
получателю. В прогулке 010 все персонажи видны всем, ресурсы нулевые.
Fog of war появится отдельной задачей до закрытых игровых данных.
HP в пределах [0,maxHp], maxHp > 0; ресурсы/время неотрицательны;
tick — неотрицательное безопасное целое; повторные ID сущностей запрещены.

Ошибки: INVALID_MESSAGE — нарушена схема/JSON; UNSUPPORTED_INTENT — игровой
обработчик ещё не реализован; RATE_LIMITED — превышена частота сообщений.
Схема не заменяет проверку игровых прав на server. Не отправлять внутренние
ошибки, содержимое конфигов или сырые сообщения обратно клиенту.

Технические пределы из shared/constants: 64 KiB на сообщение (UTF-8),
128 сущностей в snapshot, 30 сообщений на соединение за фиксированное окно 1 s,
256 KiB в очереди отправки. Binary закрывается с 1003, rate limit с 1008,
переполнение payload с 1009, отставший получатель с 1013.
Числа — ограничения транспорта, не игровой баланс.

Переподключение создаёт нового playerId в той же комнате процесса.
Сохранение сессии, учётные записи, fog of war и матчмейкинг ещё не реализованы.
Client и server декодируют внешние данные как unknown; декодеры возвращают null
при неверном формате или размере. Production-развёртывание ещё не определено.

## Базовые типы состояния (spec 003)

Источник истины — [packages/shared/src/types.ts](../packages/shared/src/types.ts),
публичный импорт типов: `@troll-vs-elves/shared`.

| Тип                | Контракт                                                    |
| ------------------ | ----------------------------------------------------------- |
| EntityId, PlayerId | Строковые идентификаторы                                    |
| Team               | `"troll"` или `"elves"`                                     |
| Phase              | `1`, `2` или `3`                                            |
| Resources          | readonly `gold`, `wood`, `rage`: number                     |
| Position           | readonly `x`, `y`: number, игровые единицы                  |
| Entity             | readonly `id`, `ownerId`, `team`, `position`, `hp`, `maxHp` |

`ownerId` равен PlayerId или null (нет игрока-владельца). Team обязателен;
нейтральные сущности в этот контракт пока не входят. Position также readonly,
поэтому координаты нельзя менять через ссылку из Entity.
Это типы TypeScript для внутреннего состояния. Они не валидируют внешний JSON,
не проверяют игровые диапазоны HP/ресурсов и не определяют WS-сериализацию.
Wire format v2 определён выше; базовые типы сами по себе не являются runtime-валидацией.

## Цикл матча (008)

Сервер рассылает полные снапшоты с частотой match.tickRateHz. Таймер стартует
с первого игрока и сбрасывается после выхода последнего. Фазы берутся из config;
на нуле время остаётся нулевым, победитель пока не определяется.

## Карта и движение (009–010)

Текущее значение PROTOCOL_VERSION=2. Welcome содержит `map: ForestMap`
(схема shared/map.ts), загруженную сервером один раз. Клиенты v1 требуют перезагрузки.

- `move(x,y)` задаёт точку в координатах карты. Сервер отклоняет недоступную цель
  с INVALID_TARGET; движение по прямой останавливается перед препятствием.
- `steer(x,y)` задаёт направление; каждая компонента в [-1,1], конечная.
  Сервер нормализует диагональ. (0,0) останавливает; новое steer заменяет move.
  Без обновления в течение 0.6 s направление истекает. Клиент повторяет его
  каждые 200 ms, при keyup/blur/скрытии вкладки отправляет ноль.
- Только сущность соединения получает интент. Сервер ограничивает скорость
  конфигом, проверяет весь отрезок движения и ограничивает задержку двумя тиками.
- INVALID_TARGET и UNSUPPORTED_INTENT не разрывают подключение.
- ROOM_FULL означает заполненную арену; соединение закрывается с 1008.
- Число участников ограничено спавнами; полный снапшот удаляет ушедших игроков.
- На нуле таймера движение заморожено, результата боя пока нет.

Временные роли: первый игрок — troll, следующие — elves. После ухода тролля
следующий вошедший занимает эту роль. Переподключение выдаёт новый ID.
