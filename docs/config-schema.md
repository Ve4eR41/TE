# Конфигурация — контракт первой версии

Статус: реализовано по spec 002.
Публичные схемы и типы: `@troll-vs-elves/shared`; загрузчик и ConfigError:
`@troll-vs-elves/shared/config/node`. Конфиги — JSON; YAML пока не поддерживается.
`rootDir` указывает непосредственно на каталог с файлами ниже.
Приведённые значения — синтетические фикстуры, не утверждённый баланс.
До spec игровой механики они не определяют реальное поведение матча.

## Обязательные файлы

| Файл             | Содержимое              |
| ---------------- | ----------------------- |
| `match.json`     | Объект параметров матча |
| `units.json`     | Массив юнитов           |
| `buildings.json` | Массив зданий           |
| `items.json`     | Массив предметов        |
| `classes.json`   | Массив классов          |
| `abilities.json` | Массив способностей     |

Пустые массивы допустимы, пропущенный файл — ошибка. Все объекты строгие:
неизвестные ключи отклоняются. ID — непустая строка без пробелов по краям,
уникальная в пределах своего файла. Числа конечные. Времена — в секундах,
расстояния — в игровых единицах. Массивы фаз и их порядок не нормализуются молча.

## Match

```json
{
  "durationSeconds": 1800,
  "tickRateHz": 20,
  "phaseStartSeconds": [0, 600, 1200]
}
```

`durationSeconds` и `tickRateHz` — положительные целые. `phaseStartSeconds` —
кортеж из трёх неотрицательных целых: первый 0, далее строго возрастают,
каждый меньше durationSeconds. Значения задаются данными, не фиксируются схемой.

## Определения сущностей

Все поля обязательны. `name` — непустая строка после trim; изменение исходных
строк схемой не допускается. HP — положительное целое; остальные показатели
в таблице — неотрицательные числа. Стоимость — объект с целыми `gold` и `wood`.

| Тип      | Поля                                                              |
| -------- | ----------------------------------------------------------------- |
| Unit     | `id`, `name`, `hp`, `speedUnitsPerSecond`, `attackDamage`, `cost` |
| Building | `id`, `name`, `hp`, `cost`                                        |
| Item     | `id`, `name`, `cost`                                              |
| Class    | `id`, `name`                                                      |
| Ability  | `id`, `name`, `cooldownSeconds`                                   |

Пример содержимого `units.json`:

```json
[
  {
    "id": "test-scout",
    "name": "Test scout",
    "hp": 100,
    "speedUnitsPerSecond": 3,
    "attackDamage": 5,
    "cost": { "gold": 10, "wood": 0 }
  }
]
```

Минимальные примеры остальных файлов:

```json
{
  "buildings.json": [
    {
      "id": "test-wall",
      "name": "Test wall",
      "hp": 100,
      "cost": { "gold": 0, "wood": 10 }
    }
  ],
  "items.json": [
    { "id": "test-item", "name": "Test item", "cost": { "gold": 1, "wood": 0 } }
  ],
  "classes.json": [{ "id": "test-class", "name": "Test class" }],
  "abilities.json": [
    { "id": "test-ability", "name": "Test ability", "cooldownSeconds": 1 }
  ]
}
```

Это иллюстрация соответствия имён файлам, а не дополнительный файл конфигурации.
Ссылки между сущностями, эффекты, rage-стоимость, карты и баланс вводятся
отдельными specs с одновременным обновлением схем, тестов и этого документа.

## Результат загрузки и ошибки

`GameConfig` содержит `match`, `units`, `buildings`, `items`, `classes`, `abilities`.
Типы выводятся из Zod, а не поддерживаются вручную параллельно.
`ConfigError extends Error` имеет `filePath`, `issues` (массив объектов
`{ path: (string | number)[]; message: string }`) и понятное сообщение.
Путь поля, например `[0, "hp"]`, сохраняется отдельно от пути файла.
Для ошибок чтения/JSON использовать пустой путь `[]`. Не раскрывать содержимое
файла в сообщениях об ошибках. Ошибка останавливает запуск; частичного конфига нет.
