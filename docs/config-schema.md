# Конфигурация — контракт первой версии

Статус: реализовано по specs 002, 009–012.
Публичные схемы и типы: `@troll-vs-elves/shared`; загрузчик и ConfigError:
`@troll-vs-elves/shared/config/node`. Конфиги — JSON; YAML пока не поддерживается.
`rootDir` указывает непосредственно на каталог с файлами ниже.
Приведённые значения — синтетические фикстуры, не утверждённый баланс.
До spec игровой механики они не определяют реальное поведение матча.

## Обязательные файлы

| Файл             | Содержимое                |
| ---------------- | ------------------------- |
| `match.json`     | Объект параметров матча   |
| `economy.json`   | Начальные ресурсы и доход |
| `units.json`     | Массив юнитов             |
| `buildings.json` | Массив зданий             |
| `items.json`     | Массив предметов          |
| `classes.json`   | Массив классов            |
| `abilities.json` | Массив способностей       |

Пустые массивы допустимы, пропущенный файл — ошибка. Все объекты строгие:
неизвестные ключи отклоняются. ID — непустая строка без пробелов по краям,
уникальная в пределах своего файла. Числа конечные. Времена — в секундах,
расстояния — в игровых единицах. Массивы фаз и их порядок не нормализуются молча.

## Match

```json
{
  "durationSeconds": 1800,
  "tickRateHz": 20,
  "phaseStartSeconds": [0, 600, 1200]
}
```

`durationSeconds` и `tickRateHz` — положительные целые. `phaseStartSeconds` —
кортеж из трёх неотрицательных целых: первый 0, далее строго возрастают,
каждый меньше durationSeconds. Значения задаются данными, не фиксируются схемой.

## Определения сущностей

Все поля обязательны, кроме явно отмеченных optional. `name` — непустая строка после trim; изменение исходных
строк схемой не допускается. HP — положительное целое; остальные показатели
в таблице — неотрицательные числа. Стоимость — объект с целыми `gold` и `wood`.

| Тип      | Поля                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| Unit     | `id`, `name`, `hp`, `speedUnitsPerSecond`, `attackDamage`, `cost`                   |
| Building | `id`, `name`, `hp`, `cost`, `radius`, `buildRangeUnits`, `maxPerPlayer`, `upgrade?` |
| Item     | `id`, `name`, `cost`                                                                |
| Class    | `id`, `name`                                                                        |
| Ability  | `id`, `name`, `cooldownSeconds`                                                     |

Пример содержимого `units.json`:

```json
[
  {
    "id": "test-scout",
    "name": "Test scout",
    "hp": 100,
    "speedUnitsPerSecond": 3,
    "attackDamage": 5,
    "cost": { "gold": 10, "wood": 0 }
  }
]
```

Минимальные примеры остальных файлов:

```json
{
  "buildings.json": [
    {
      "id": "test-wall",
      "name": "Test wall",
      "radius": 24,
      "buildRangeUnits": 160,
      "maxPerPlayer": 6,
      "hp": 100,
      "cost": { "gold": 0, "wood": 10 }
    }
  ],
  "items.json": [
    { "id": "test-item", "name": "Test item", "cost": { "gold": 1, "wood": 0 } }
  ],
  "classes.json": [{ "id": "test-class", "name": "Test class" }],
  "abilities.json": [
    { "id": "test-ability", "name": "Test ability", "cooldownSeconds": 1 }
  ]
}
```

Это иллюстрация соответствия имён файлам, а не дополнительный файл конфигурации.
Ссылки между сущностями, эффекты, rage-стоимость, карты и баланс вводятся
отдельными specs с одновременным обновлением схем, тестов и этого документа.

## Результат загрузки и ошибки

`GameConfig` содержит `match`, `economy`, `units`, `buildings`, `items`, `classes`, `abilities`.
Типы выводятся из Zod, а не поддерживаются вручную параллельно.
`ConfigError extends Error` имеет `filePath`, `issues` (массив объектов
`{ path: (string | number)[]; message: string }`) и понятное сообщение.
Путь поля, например `[0, "hp"]`, сохраняется отдельно от пути файла.
Для ошибок чтения/JSON использовать пустой путь `[]`. Не раскрывать содержимое
файла в сообщениях об ошибках. Ошибка останавливает запуск; частичного конфига нет.

## Карта (009)

`loadMap(rootDir)` отдельно читает `maps/forest.json` через тот же ConfigError.
Схема `forestMapSchema` в shared: id=forest, width/height (единицы мира),
bounds (left/right/top/bottom), avatarRadius, непустой список spawns,
trees (x,y,scale,ancient?), pond и obstacles (x,y,radiusX,radiusY).
Все координаты конечны, размеры положительны. Границы должны помещаться в карту,
спавны — в доступную область с учётом радиуса. Эллипсы расширяются на радиус
персонажа; это консервативная модель коллизий тестовой арены.
Массив спавнов ограничивает число одновременных игроков. Параметры временные.

## Персонажи прогулки (010)

`units.json` содержит временные определения id=troll и id=elves. Сервер требует
оба с положительной speedUnitsPerSecond. HP: 100/60, скорость: 145/180 единиц/с;
attackDamage=0, cost={gold:0,wood:0}. Эти значения нужны только для пробы движения,
баланс и бой пока не определены. Радиус коллизии общий из карты.

## Экономика (011)

GameConfig включает economy из economy.json. Строгая economySchema содержит
starting и incomePerSecond: по troll/elves объект {gold,wood,rage}; конечные
неотрицательные числа. Единицы дохода — в секунду. Для теста эльф начинает со
120 золота/120 дерева, получает 2/3 в секунду. Тролль и ярость пока без дохода.
Все значения временные. Дроби сохраняются на сервере, клиент показывает пол.

## Стены (012)

BuildingConfig: обязательны положительные radius/buildRangeUnits (единицы мира),
maxPerPlayer (целое 1..128). Необязателен upgrade {hp,cost}, hp строго выше
исходного. Остальная валидация HP и цен сохраняется. Пример актуального конфига:

```json
{
  "id": "wall",
  "name": "Лесная стена",
  "hp": 200,
  "radius": 24,
  "buildRangeUnits": 160,
  "maxPerPlayer": 6,
  "cost": { "gold": 30, "wood": 40 },
  "upgrade": { "hp": 400, "cost": { "gold": 40, "wood": 30 } }
}
```

Параметры пробы: стена стоит 30 золота/40 дерева, улучшение 40/30, HP 200→400;
максимум шесть стен владельца. Это временные значения. Все стены исчезают при
выходе владельца, без возврата ресурсов. Глобальный предел состояния — технический
MAX_SNAPSHOT_ENTITIES с резервом для всех спавнов. Форма коллизии — круг radius.

## Найм стражей (013)

UnitConfig допускает optional `recruitment` (у героев отсутствует):
`radius > 0`, `maxPerPlayer` целое1..128, `aggroRangeUnits > 0`,
`0 < stopRangeUnits < aggroRangeUnits`; все числа конечны.
`spawnOffsets` — от1 до128 объектов `{x,y}` с конечными смещениями в единицах
карты относительно владельца; порядок задаёт приоритет поиска свободной точки.
Никакой загрузки на каждом тике: всё читается при старте вместе с units.json.

Пробный guard: HP80, скорость110, урон0, цена40gold/20wood; radius12, лимит3,
обнаружение240, остановка36. Смещения: (±48,0),(0,±48),(±34,±34).
Это временные значения для проверки найма/AI, финальный баланс не определён.
Числа и полный пример: [units.json](../config/units.json).
